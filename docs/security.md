## 3. Deployment controls (verified on the live service, Day 4.11 and 4.15)
- CORS allows only the production origin (a trailing-slash mistake in the configured value blocked the site once; the backend now normalises it and warns about malformed entries). Proxy trust: `X-Forwarded-For` is read as "Nth entry from the right" with N = 3, measured on Render, so forged entries on the left cannot change the rate-limit key; IPv6 clients are keyed by their /64.
- Rate limits per visitor (30 per minute on /chat and /scan, 120 per minute overall), request-size caps (also re-checked after Unicode normalisation), a **global** daily cap on AI calls (500) and a **per-visitor** daily allowance (40). Counters are in memory and reset when the free server restarts.
- The event log stores no message, reply or placeholder text (whitelisted columns only); fingerprints are keyed with a secret.
- Headers on the site: `nosniff`, referrer policy, frame denial and a Content-Security-Policy limited to images, objects, base URI, framing and forms. **There is no script/connect CSP yet**: the app needs WebAssembly, workers and Hugging Face connections, and a wrong policy would silently break model loading; listed as a hardening to-do.

## 4. Independent review (Day 4.17; one read-only reviewer for bugs and security, one for claims against evidence)
Security and bug findings, with what was done: partial scans reaching the AI (fixed: blocked by default), links in the AI's reply that carry restored personal data (fixed: such links render as text), canary encodings missed by the output scanner and no NFKC normalisation (fixed: base64/base32 at every alignment, rot13, code points, NFKC), length cap checked before Unicode expansion (fixed: re-checked after), one visitor able to drain the global AI budget and counters resetting on restart (fixed in part: per-visitor allowance; the restart reset is a documented limit), IPv6 /64 keying (fixed), unpinned name-model revision (fixed: pinned to the evaluated commit), no request timeout in the browser (fixed: 90 s), missing CSP (partly: image/object/frame/base/form directives only), stale comments and an unpinned `huggingface_hub` (fixed). Not changed: GitHub Actions are pinned by major tag, not commit SHA; the base image is a floating tag; `requirements.lock.txt` has no hashes; the public `/stats` endpoint shows the last 20 events (verdict, score, timing, no text) to anyone, which is rate-limited and disclosed on the Dashboard; browser-side normalisation removes hidden characters before sending, so the server's "hidden characters" warning does not fire for browser traffic. Full list: `docs/decisions.md` Day 4.17.

Day 4.19 follow-up: the live Dashboard showed that a dense input refused as "partial" still cost 9 to 10 s of CPU because six windows were scanned first, which one visitor could use to keep the 0.15 vCPU server busy. Such inputs are now refused right after tokenising (milliseconds, no inference). Long *legitimate* documents still cost up to about 7 s (four windows) and remain a limit of the free tier.
